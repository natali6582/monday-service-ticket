## למה הטופס מוחלף ולא רק מעוצב

עץ הנושאים הדו-שלבי דורש **רשימה תלוית-בחירה** — תת-הנושא נטען לפי הנושא. אלמנט Wix Forms
המובנה לא עושה את זה. לכן גוף הטופס נבנה מאלמנטים בודדים שקוד העמוד מנהל.

**אבל השליחה עצמה נשארת דרך Wix Forms** — `backend/support.jsw` יוצר את ה-submission
דרך ה-Form Submissions API. המשמעות: האוטומציה הקיימת נשארת מחוברת ל"טופס נשלח", ממשיכה
ליצור את הקונטקט, לשלוח את מייל האישור (`VPeL0Z3`) ואת ההתראה הפנימית, וממשיכה להריץ את
`monday_ticket.js` — **בלי שינוי אחד**.

> ⚠️ **שער האימות היחיד.** לא הצלחתי לאמת שיצירת submission דרך ה-API מפעילה את
> האוטומציה של האתר. **זה הדבר הראשון לבדוק** (שלב 7). אם לא — יש תוכנית גיבוי בסוף המסמך.

## שלב 2 — הטופס המקורי נשאר, מוסתר

אל תמחקי את אלמנט Wix Forms מהעמוד המשוכפל. הוא עדיין המנגנון שמפעיל את האוטומציה.

1. בחרי את אלמנט הטופס
2. שדות שצריך שיהיו בו (יתווספו אם חסרים): `שם מלא`, `שם המשרד`, `מייל`, `טלפון`,
   `נושא הבעיה`, `תת-נושא`, `פירוט נושא`, `קישור למסך שבו נתקלתם בבעיה (URL)`, `תיאור התקלה`
   — כולם כשדות **טקסט חופשי**. הם לא מוצגים למשתמש, רק מקבלים את הערכים
3. לכל שדה: settings → **Field key** → העתיקי את המפתח לטבלה בשלב 5
4. הגדרות הטופס → העתיקי את **Form ID**
5. את האלמנט עצמו: **Hide on load** (לא Delete)

### מזהי האלמנטים — חייבים להיות בדיוק אלה

קוד העמוד זורק שגיאה בטעינה אם אלמנט חסר, בכוונה — כדי שתגלי את זה מיד ולא כשלקוח שולח.

| מזהה | סוג | הערות |
|---|---|---|

| `#inputOfficeName` | Text Input | `שם המשרד *` |

| `#inputPhone` | Text Input (phone) | `טלפון *` |

| `#dropdownSubtopic` | Dropdown | `תת-נושא *` — ריק, **Collapse on load** |
| `#dropdownDetail` | Dropdown | ריק, **Collapse on load** |

### מיקרו-קופי — להעתיק כלשונו (v1.2 §05)

| מקום | טקסט |
|---|---|
| כותרת | פתיחת קריאת שירות |
| הסבר | נתקלתם בתקלה או שיש לכם שאלה? מלאו את הפרטים ונפתח עבורכם קריאת שירות. בסיום תקבלו מספר פנייה למעקב, ומנהל קשרי הלקוחות שלנו ילווה אתכם באופן אישי עד לפתרון. |
| עזרה למייל | לכתובת זו יישלחו אישור הפתיחה והעדכונים על הקריאה |
| עזרה ל-URL | העתיקו את הכתובת מסרגל הכתובת של הדפדפן והדביקו כאן — כך נגיע ישירות למסך הרלוונטי. |
| placeholder לתיאור | מה ניסיתם לעשות, מה קרה בפועל, והאם זה חוזר על עצמו? |
| אזהרת פרטיות | נא לא לציין שם לקוח או מספר ת״ז בתיאור. משיקולי אבטחת מידע לא ניתן לצרף קבצים — אם יידרשו, נציג יבקש אותם בערוץ מאובטח. |
| כפתור | פתיחת קריאה |
| אישור — כותרת | הקריאה נפתחה |

**מסך האישור — גוף (`#groupConfirm`):**

> פתחנו עבורכם קריאת שירות ושלחנו מייל אישור עם מספר הפנייה למעקב.
>
> הפנייה תיבחן על ידי מנהל קשרי הלקוחות, וכשתעבור לטיפול — יישלח אליכם עדכון נוסף במייל. מכאן הליווי אישי עד לפתרון.

> **סטייה מודעת מ-v1.2.** האפיון מציג את מספר הפנייה על המסך. בהחלטה שלך, שלב א' בלי מספר
> על המסך — הוא מגיע במייל האישור. הסיבה: המספר נוצר בתוך האוטומציה, אחרי שהעמוד כבר סיים.
> להציג אותו בזמן אמת דורש הזרמה סינכרונית — שינוי גדול יותר בפרודקשן.

ב-`backend/support.jsw`, מלאי שני דברים:

```js
const SUPPORT_FORM_ID = '';   // ← Form ID משלב 2.4

const FIELD_KEYS = {
  fullName: '',      // ← field key של 'שם מלא'
  officeName: '',    // ← 'שם המשרד'
  email: '',         // ← 'מייל'
  phone: '',         // ← 'טלפון'
  topic: '',         // ← 'נושא הבעיה'
  subtopic: '',      // ← 'תת-נושא'
  topicDetail: '',   // ← 'פירוט נושא'
```

אלה **field keys**, לא תוויות. הקוד זורק שגיאה מפורשת אם משהו נשאר ריק — לא ייכשל בשקט.

## שלב 7 — אימות, לפני כל פרסום

### 7א · שער חובה — האם submission מ-API מפעיל את האוטומציה?

1. פרסמי את `support-v34` (מוסתר מתפריט ומחיפוש)

| תוצאה | משמעות |
|---|---|
| ✅ נוצר פריט | האדריכלות עובדת. המשיכי ל-7ב |

## תוכנית גיבוי — אם 7א נכשל

אם submission מ-API לא מפעיל את האוטומציה, יש שני מסלולים:

**מסלול א' (מומלץ) — Velo code trigger.** האוטומציה כבר מכירה את התבנית הזאת: הקוד
משתמש בה להתראה הפנימית (`customTrigger.runTrigger`). צריך:

1. אוטומציה חדשה עם טריגר **Velo code trigger**, להעתיק את ה-trigger ID
2. הפעולה שלה: אותו `monday_ticket.js`
3. ב-`support.jsw`, להחליף את `createSubmission` ב-`runTrigger`
4. **חשוב:** payload של custom trigger הוא שדות שטוחים, לא מערך. צריך שכבת המרה קטנה
   בתחילת `invoke` שממירה שדות שטוחים ל-`submissions` — או להעביר את המערך כ-JSON string
   ולפרסר אותו. `buildSubmissionLookup` נשאר ללא שינוי
5. הקונטקט למייל האישור: `emailContact` דורש `contactId`, שהטופס נתן בחינם. במסלול הזה
   צריך ליצור/למצוא את הקונטקט ב-`support.jsw` דרך `wix-crm-backend`

**מסלול ב' (זול, פחות טוב) — טופס Wix מובנה בלי עץ.** משאירים את הטופס כמו שהוא ומוותרים
על התלות בין נושא לתת-נושא: תת-נושא הופך לרשימה שטוחה של כל 28 הערכים. העיצוב והמיקרו-קופי
מיושמים במלואם, העץ לא. פחות טוב למשתמש, אפס סיכון אדריכלי.
